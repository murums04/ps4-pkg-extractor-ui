# Building

Use Python 3.12 and the pinned packages in `requirements-build.txt`. Build on the destination OS and architecture. No cross-platform binary is generated by a Windows-only build.

## Windows x64

Install Python 3.12, Git, Inno Setup 6 or 7 and MSYS2. In the MSYS2 UCRT64 terminal, install the native build dependencies:

```sh
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja mingw-w64-ucrt-x86_64-crypto++ mingw-w64-ucrt-x86_64-zlib
```

From PowerShell in the source folder:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-build.txt
$env:PATH = "C:/msys64/ucrt64/bin;" + $env:PATH
.venv/Scripts/python.exe scripts/build.py --iscc "C:/Program Files (x86)/Inno Setup 6/ISCC.exe"
```

The build verifies the pinned extractor sources, applies the encrypted-entry correction to a build-directory copy and compiles the engine. It embeds the UTF-8 manifest, collects dependency notices, runs tests, builds the app, creates ZIP/setup/source packages and checks the packaged program. Outputs are under `packages/`; `packages/local/ps4-pkg-extractor-ui` is runnable.

Windows 10 version 1903 or newer is required by the UTF-8 process code page. The manifest change uses `scripts/windows_manifest.py` and `packaging/backend-windows.manifest`. The extractor links Crypto++, zlib and the GCC/MinGW runtime statically; its remaining DLL imports are Windows system libraries.

## macOS arm64 or x64

Use a native Python for the intended architecture. Install native dependencies with Homebrew:

```sh
brew install cmake cryptopp zlib
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-build.txt
export CMAKE_PREFIX_PATH="$(brew --prefix):$(brew --prefix zlib)"
export MACOSX_DEPLOYMENT_TARGET=15.0
.venv/bin/python scripts/build.py
.venv/bin/python scripts/verify_native_installers.py
```

The pinned extractor source builds with C++23. PyInstaller collects its dependencies into the app. Packaging creates an ad-hoc signed `.app`, a portable ZIP and a DMG with an Applications link. No Apple Developer certificate or notarization is configured.

`packaging/native/compatibility.h` supplies a missing standard-library include and the Darwin `fseeko` name without editing the pinned upstream sources.

## Linux x64

Use Ubuntu 22.04 or newer. The workflow lists the Qt/X11 runtime dependencies. Native builds also need `cmake`, `g++-12`, `libcrypto++-dev`, `zlib1g-dev`, `xvfb` and `dpkg-dev`.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-build.txt
export CXX=g++-12
xvfb-run -a .venv/bin/python scripts/build.py
xvfb-run -a .venv/bin/python scripts/verify_native_installers.py
```

The build compiles the same pinned extractor source, collects native library license records and creates a DEB and portable tar.gz. It does not depend on an AppImage mount or FUSE.

## Development and tests

After preparing the backend:

```sh
python scripts/fetch_backend.py
python -m pytest -q
python scripts/capture_ui.py
```

Use the virtual environment's Python. For a source launch, install the package with `python -m pip install -e .`, then run `ps4-pkg-extractor-ui`. Keep `assets/` and `backend/` in the source root. Wheels alone are not standalone distributions.

Headless extraction:

```sh
ps4-pkg-extractor-ui --extract example.pkg --output-dir extracted --report result.json
```

Reports must use a new filename. Completed extractions use numbered alternative folders.

The source-vendoring script verifies each downloaded file against the pinned Git tree. Normal builds use the included sources and do not refresh them. `scripts/verify.py distribution` rechecks their identities.

The native checks verify archive checksums, extract each portable download, extract the DEB payload or mount/copy the DMG, and run the packaged app from each copy. They check native Qt startup, exact synthetic extraction, unchanged inputs and rejection of invalid packages. macOS checks also verify the app architecture and ad-hoc signature.

On a disposable Linux build machine, add `--install` to test system installation, reinstallation and removal. This check refuses to replace an existing app installation. The workflow uses this option.

The Windows installer check performs a temporary installation and uninstall; it needs normal access to the current user's Start menu and uninstall registry.
